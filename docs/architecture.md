# Архитектура: технологический стек и компоненты

## Компоненты
- **Frontend SPA** — React + TypeScript + Vite. Канвас на react-flow (узлы/связи/зум из коробки). Авто-раскладка кластерных графов (проекты как контейнеры) — elkjs. WebSocket-клиент для live-исполнения сценария.
- **Backend** — Java + Spring Boot, модульный монолит (совпадает с текущим стеком разработчика — не тратим время на изучение нового языка/фреймворка). Модули:
  - Domain API — CRUD Project / Scheme / Block Instance / Entry Point / Scenario / Scenario Step
  - Execution Engine — рекурсивный интерпретатор ScenarioStep, публикует события исполнения
  - Versioning — история изменений Scheme / Scenario / Entry Point
  - Sharing & RBAC — шаринг по ссылке, роли Owner / Editor / Reader
  - Границы модулей проектируются так, чтобы при необходимости любой модуль можно было вынести в отдельный сервис позже (например, Execution Engine — первый кандидат при росте нагрузки)
- **PostgreSQL** — основное хранилище. Реляционная модель + JSON-поля под гибкие конфиги блоков. Одинаково хорошо работает как managed-сервис в облаке и в Docker-контейнере на своей инфраструктуре — закрывает NFR по self-hosted.
- **Realtime-канал** — WebSocket (STOMP, встроенная поддержка в Spring) для потока событий исполнения сценария к фронтенду.

## Решение: монолит, а не микросервисы (для MVP)
Соло-разработка — распределённая система (service discovery, межсервисные транзакции, деплой N сервисов) добавляет инфраструктурные издержки без выгоды, которую микросервисы дают большим командам. Модульная структура внутри монолита сохраняет возможность декомпозиции в будущем без переписывания домена.

## Деплой
Docker Compose как первый уровень self-hosted упаковки: backend + PostgreSQL + frontend (статическая сборка за nginx) поднимаются одной командой на сервере команды. Kubernetes не рассматривается на этом этапе — решение отложено до появления реальной потребности в масштабировании.

## Технологические решения, принятые в этом раунде
- Frontend: React + TypeScript + Vite + react-flow + elkjs (решение делегировано Claude — у Саши нет опыта фронтенда)
- Backend: Java + Spring Boot, модульный монолит (совпадает с текущим стеком)
- Хранилище: PostgreSQL
- Realtime: WebSocket / STOMP
- Деплой (MVP): Docker Compose

## Открытые вопросы для следующего этапа
- Контракт API между Frontend и Backend (REST-эндпоинты, схема WebSocket-событий исполнения)
- Модель хранения версий: полные снэпшоты vs дельты
- Структура репозитория (моно-репо frontend+backend или раздельно)
