# Бриф для UI/UX-агента (Claude Code / Claude Design)

Ты подключаешься к уже рабочему проекту (`lowcode-platform`, React 18 +
TypeScript + Vite + react-flow) — весь функционал реализован и протестирован
вживую владельцем проекта через долгую серию итераций. Твоя задача —
**презентационный слой**: layout, стили, типографика, иконки, общее
ощущение "не самодельно". НЕ бизнес-логика, НЕ структура состояния.

## Прочитай сначала

- `README.md` — вся история решений и известные ограничения. Особенно
  разделы "ScenarioBuilder", "Флоу создания через UI", "Аутентификация".
- `docs/vision-and-scope.md`, `docs/functional-requirements.md`,
  `docs/ui-prototype.html` — исходное видение UI (сделано ДО текущей
  реализации, местами разошлось с тем, что реально есть сейчас — ориентир
  по духу, не буквальная спецификация).

## Что можно менять свободно

- `frontend/src/**/*.css`, инлайн-стили (`style={{...}}`) — сейчас почти
  везде голый инлайн-CSS без дизайн-системы, это и есть основная работа
- Разметка (JSX-структура/вложенность div'ов, классы) — если меняешь ради
  layout, а не ради логики
- `frontend/src/creation/Modal.tsx` — общий модал, дёшево причесать один раз
  и получить эффект везде
- Иконки для типов блоков (`ACTOR`/`MICROSERVICE`/`DATABASE`/
  `MESSAGE_BROKER`/`CACHE`/`USER`) — сейчас это просто текст `label · CODE`
  на узле react-flow (`SchemeCanvas.tsx`/`ScenarioBuilderNodes.tsx`)
- Цветовая палитра/типографика — сейчас в основном tailwind-подобные hex
  (`#2563eb`, `#16a34a`, `#94a3b8`...) вручную по всему коду, россыпью, без
  единого источника — стоит завести токены (хоть CSS-переменные, хоть
  объект констант) и провести через все компоненты

## Что НЕ трогать (или трогать только зная, зачем)

- `frontend/src/api/*.ts` — вся сетевая логика; здесь уже был минимум один
  болезненный баг с гонкой состояний (React state timing), не добавляй
  новых side-effect'ов сюда
- `useEffect`/`useCallback`/`useMemo` и их массивы зависимостей в
  `canvas/ScenarioBuilder.tsx` и `canvas/SchemeCanvas.tsx` — там уже был
  реальный инфинитный цикл сетевых запросов из-за нестабильной зависимости
  (см. историю в README/git log), обе логики сейчас корректны и хрупки к
  рефакторингу. Если нужно поменять JSX внутри этих файлов — меняй
  разметку/стили, не трогай тело хуков
- Домены/эндпоинты в `api/*.ts` — не придумывай новые REST-вызовы, весь
  контракт бэкенда описан в `docs/api-contract.md`; если для дизайна не
  хватает данных с backend — не мокай, скажи владельцу проекта, обсудим
  отдельно (не мне — ему, я тут не участвую в вашей сессии)

## Инвентарь компонентов (что где)

```
App.tsx                         — шапка с переключателем режимов, auth-гейт
auth/LoginScreen.tsx             — экран логина/регистрации
canvas/SchemeCanvas.tsx          — "Редактор схемы" + "Запуск сценария" (два режима в одном файле)
canvas/ScenarioBuilder.tsx       — экран "Сценарии" (сборка цепочки вызовов)
canvas/ScenarioBuilderNodes.tsx  — кастомные react-flow узлы для ScenarioBuilder
canvas/TokenEdge.tsx             — анимированный токен на стрелке (run mode)
canvas/graphLayout.ts            — elkjs-раскладка мульти-проектного графа (НЕ презентационное, не трогать)
creation/*.tsx                   — модалки создания (проект/блок/entry point/сценарий)
```

## Известные особенности, которые дизайну стоит учитывать

- **Три режима** (не подстраницы — переключаются кнопками в шапке): Редактор
  схемы, Сценарии, Запуск сценария. Каждый режим показывает разные вещи для
  одного и того же проекта.
- **react-flow канвас** — основной визуальный элемент почти everywhere.
  Кастомные узлы/рёбра уже пишутся вручную (не библиотечные дефолты) — если
  меняешь их вид, делай через `nodeTypes`/`edgeTypes` (см. существующие
  примеры), не через глобальные CSS-хаки поверх react-flow internals.
- **Модалки** — простые, без анимаций открытия/закрытия, без esc-to-close.
- **Ошибки** — просто текст красным под формой (`color: '#dc2626'`), без
  toast/snackbar системы.
- Данные из backend **асинхронные** — везде нужны loading/empty/error
  состояния, сейчас они есть, но неказистые (голый текст).

## Как отдавать работу обратно

Договоритесь с владельцем проекта: либо отдельная git-ветка (если репозиторий
уже на GitHub — см. README, раздел "Бэклог: рабочий процесс разработки"),
либо просто набор изменённых файлов. Перед сдачей прогони сам:
```bash
cd frontend
npm install
npx tsc -b        # обязательно — должно быть чисто
npx vite build    # обязательно — должно собираться
```
Если `tsc`/`vite build` не проходят — это не готово к сдаче, а не "мелкая
недоделка, само пройдёт".
